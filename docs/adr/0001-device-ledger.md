# ADR 0001：以设备为聚合根的运行态台账

- 状态：已采纳（2026-11-23）
- 背景：运维需要一份全网运行态基本面，用来查端口、互联、IP 位置、光模块、错包与风险。设备来自 H3C、Cisco NX-OS 等多个厂商，回显格式差异大。仓库里已有 netops（解析、证据、规则、存储）与 net-connector（会话）。

## 决定

1. **建模方式**
   - 以 `Device` 为聚合根，按对象组合建模：System、Stack、Interface、Transceiver、Aggregate、Bridging、Routing、Neighbor。
   - 厂商语法只出现在 `vendors/<厂商>` 中。分析和规则只读模型。
2. **解析引擎**
   - 统一用 netops `parse` 与 `evidence` 解析回显，用户已确定，不引入 ntc-templates。
   - 每条命令都统计未消费行，格式漂移时维度降为 partial，不静默丢数据。
   - LLDP list 复用 netops `neighbor` 做计数核对。
3. **存储**
   - 只用 JSON 文件，用户已确定。按批次通过 netops `store` 原子写入。
   - 分析时全量加载并在内存中建索引。800 台规模下单次查询约 2 秒。
4. **风险规则**
   - 用 netops `assess` 实现。每条规则声明依赖的维度，未采到时跳过规则，不报告为"正常"。
5. **一期范围**：H3C Comware 与 NX-OS，覆盖语料中 830 台里的 799 台。

## 后果

- 新厂商只需在 `vendors/` 下新增一个包，并在 registry 中登记别名。
- 台账可由原始快照重放生成，解析器升级后不必重新采集。
- 全量加载的 JSON 在万台规模时需要加索引文件，或改用其它存储，届时另立 ADR。
